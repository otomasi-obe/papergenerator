LANGKAH 1 -- Analisis temuan baru
  Untuk template `ICET`, temuan berikut muncul:
    - KATEGORI 3: STYLE & FONT: 9 masalah
    - KATEGORI 4: TABLE LAYOUT CONTAINER: 1 masalah

  Pertanyaan kunci yang harus dijawab sebelum mengubah checker:
    a. Apakah pola anomali ini SUDAH ditangkap oleh audit existing,
       hanya saja threshold-nya kurang tepat? (=> tune threshold)
    b. Apakah pola ini BENAR-BENAR baru, belum ada audit-nya?
       (=> tambah audit function baru)
    c. Apakah finding ini false-positive untuk template-style ini?
       (=> tambah whitelist/exclusion, JANGAN hapus check global)

LANGKAH 2 -- Pilih strategi upgrade (urut dari paling aman)
  [A] Tune threshold existing
      Contoh: TABLE_COUNT_TOLERANCE, SECTPR_DISTRIBUTION_THRESHOLD,
      PARAGRAPH_STYLE_CHECK_COUNT. Ubah hanya bila pola yang
      terdeteksi konsisten muncul di >=2 template berbeda.

  [B] Tambah sub-check di audit existing
      Bila finding-nya varian dari kategori existing (mis. table
      count meleset karena pattern figure-wrapper), tambahkan
      cabang khusus di `audit_table_count()` atau sejenisnya
      sehingga pesan error lebih spesifik (sebut pattern-nya).

  [C] Tambah audit function baru
      Bila pola benar-benar di luar 7 kategori existing, buat
      `audit_<nama>()` baru yang return `AuditResult`, daftarkan
      di `main()`, dan tambahkan render-nya di `render_report()`.
      Konvensi: MAYOR untuk struktural, MINOR untuk visual.

LANGKAH 3 -- Validasi sebelum commit
  - Run checker terhadap SEMUA file output existing (DJLIT, SAGE,
    JCEF, dll) untuk pastikan tidak ada regresi false-positive.
  - Untuk template yang sebelumnya 'Lulus', skornya harus tetap
    >= skor sebelumnya. Bila ada penurunan, threshold/check baru
    terlalu agresif -- mundur atau perlonggar.
  - Tambahkan komentar di check baru yang menyebut template
    sumber pola: '# Pattern asal: template ICET (run YYYY-MM-DD)'
    supaya jejak rule traceable di git history.

LANGKAH 4 -- Hindari over-fitting
  - JANGAN bikin rule yang hanya men-deteksi kasus persis di
    `ICET` (mis. hard-code nilai twip atau nama style).

  - JANGAN hapus/loosen check existing hanya supaya template ini
    'lulus'. Kalau check existing salah, perbaiki rumusnya, bukan
