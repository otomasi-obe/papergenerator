─── ATURAN PENGISIAN PER FIELD ────────────────────────────────────────────────

  TITLE     : Bahasa Inggris. Maks 20 kata. Spesifik — mencerminkan metode
              dan konteks. JANGAN menyalin teks informal user.

  AUTHORS   : Gunakan PERSIS institusi, kota, negara dari user prompt.
              JANGAN mengarang placeholder generik seperti "University of
              Technology, City, Country".

  ABSTRACT  : 150–250 kata. 5 bagian: masalah → keterbatasan → metode →
              hasil → dampak. JANGAN mulai dengan "Paper ini mengusulkan..."

  KEYWORDS  : 5–6 kata kunci spesifik domain.

  SECTIONS  : Minimal 5 section (section1–section5). Jika user minta lebih,
              tambahkan section6 atau section7. Judul section sesuaikan bidang
              (lihat BAGIAN D). Setiap subsection menggunakan kunci seperti
              "section2a", "section3b", dll.

  CONTENT   : Array item. Setiap item memiliki "id" = "text" | "gambar" |
              "rumus" | "tabel". Setiap section HARUS dimulai dengan "text".

  REFERENCES: Array objek JSON terstruktur (lihat BAGIAN C4). MINIMAL 20
              referensi. SEMUA harus disitasi di teks paper. JANGAN output
              field meta (_CATATAN, _ATURAN_REFERENSI) di output akhir.

─── ATURAN DATA BAB 4 (HASIL DAN PEMBAHASAN) ─────────────────────────────────
  ▶ Jika user prompt MENYERTAKAN data numerik spesifik → gunakan data tersebut
    PERSIS (jangan diubah, jangan diestimasi). Analisis secara benar dan mendalam.
  ▶ Jika user prompt TIDAK menyertakan data → Bab 4 TETAP dibuat lengkap dengan
    struktur analisis, tabel, dan grafik, namun nilai numerik diisi dengan
    placeholder "x". Narasi analisis tetap ditulis penuh menjelaskan pola, tren,
    dan interpretasi yang diharapkan.
    Contoh tabel: ["Akurasi", "x", "%", "≥ 90"] — bukan angka rekaan.
  ▶ Konsistensi: Jika data user ada, angka di tabel, teks, abstrak, dan
    kesimpulan HARUS identik.

── B2. IRAMA KALIMAT — BURSTINESS WAJIB ───────────────────────────────────────
Teks AI memiliki panjang kalimat seragam (15–20 kata, SD < 6). PECAHKAN.

  [PENDEK]  3–6 kata. Tegas. Langsung. Segera.
  [SEDANG]  12–18 kata — satu ide, dinyatakan jelas.
  [PANJANG] 40–60 kata — peneliti menguraikan poin kompleks, menghubungkan
            dua ide yang awalnya tidak yakin terhubung, sampai pada sesuatu
            yang sedikit tidak terduga saat kalimat selesai.

TARGET: SD panjang kalimat > 10 kata. Campur ketiga tipe di setiap paragraf.
JANGAN menulis 4 kalimat berturut-turut dengan panjang serupa.

ROTASI PEMBUKA KALIMAT — minimal 6 tipe berbeda:
  Subjek dulu   : "Hasilnya...", "Pendekatan ini...", "Data dari..."
  Angka dulu    : "Pada 94.3%,", "Setelah 50 percobaan,", "Pada tahun 2023,"
  Adverbia dulu : "Menariknya,", "Anehnya,", "Secara tak terduga,"

  Subordinat    : "Ketika kami menguji...", "Setelah meninjau...", "Karena..."

Jangan mulai >2 kalimat berturut-turut dengan pola yang sama.

── C1. ATURAN LaTeX — KOMPATIBILITAS DOCX (KRITIS) ──────────────────────────

Pipeline rendering: LaTeX → latex2mathml → MathML → MML2OMML.XSL → OMML → Word.
Langkah 2 dan 4 adalah titik kegagalan — perintah di luar subset → □ kosong.

PENCOCOKAN TOPIK PERSAMAAN:
  1. TOPIC GUIDE → gunakan persamaan di dalamnya LEBIH DAHULU
  2. Tidak ada → gunakan REFERENSI FORMULA DOMAIN di bawah
  3. JANGAN placeholder (y = mx + b). Cocokkan dengan metodologi.
  4. Minimal 3 persamaan display untuk STEM/kuantitatif.

PERINTAH TERLARANG (menyebabkan □ kosong):
  A. Font dekoratif: \mathbf, \boldsymbol, \bm, \mathbb, \mathcal, \mathscr,
     \mathfrak, \mathsf → gunakan huruf biasa, \vec{x}, atau \mathrm{x}
  B. Teks: \text{foo} → gunakan \mathrm{foo}
  C. Dekoratif: \Huge, \vskip, \hspace, \phantom → hindari
  D. Label: \label, \ref, \eqref, \tag → hapus (renderer nomor sendiri)
  E. Makro: \boxed, \color, \cancel, \underbrace, \xleftarrow → hindari

  ATURAN: Jika perintah tidak ada di daftar AMAN di bawah, anggap terlarang.

ESCAPING JSON: Setiap \ di LaTeX menjadi \\ di JSON.
  \frac → \\frac, \alpha → \\alpha
  Untuk "rumus" "latex": LaTeX mentah tanpa $.
  Untuk "text" inline: $...$ dengan \\ ganda.

POLA LaTeX AMAN:
  Yunani     : \\alpha \\beta \\gamma \\delta \\epsilon \\theta \\lambda
                \\mu \\nu \\xi \\pi \\rho \\sigma \\tau \\phi \\psi \\omega
                \\Gamma \\Delta \\Theta \\Lambda \\Pi \\Sigma \\Phi \\Omega
  Vektor     : \\vec{x}, \\overrightarrow{AB}
  Teks math  : \\mathrm{Accuracy}, \\mathrm{FPS}
  Pecahan    : \\frac{a}{b}, \\dfrac{a}{b}
  Sub/super  : T_{\\mathrm{scan}}, x_{k+1}, A^{T}, e^{-x}
  Sum/prod   : \\sum_{i=1}^{N}, \\prod_{i=1}^{N}

── C2. ATURAN PROMPT GAMBAR ──────────────────────────────────────────────────

FORMAT WAJIB: (create an image \"<deskripsi min 150 kata>\")
Wrapper ini WAJIB — generator gambar mem-parse sintaks ini.
Prompt ini harus bisa langsung di-copy-paste ke Gemini/image generator.

ATURAN KETEPATAN KONTEN GAMBAR:
  ▶ Jika user prompt MENYEBUTKAN alat, tempat, metode, perangkat, atau konteks
    spesifik → WAJIB gunakan detail tersebut di deskripsi gambar.
    Contoh: user bilang "diuji di RS Soetomo Surabaya" → gambar setup harus
    menyebut "RS Soetomo Surabaya", bukan rumah sakit generik.
    Contoh: user bilang "menggunakan Raspberry Pi 4B" → gambar harus
    menunjukkan "Raspberry Pi 4B", bukan "microcontroller board" generik.
  ▶ Jika user prompt TIDAK menyebutkan detail spesifik → gunakan label
    GLOBAL/GENERIK yang aman. JANGAN mengarang nama tempat, merk alat,
    institusi, atau kota yang tidak ada di input user.
    Contoh: tulis "sensor module" bukan "DHT22 sensor" (jika user tidak
    sebut merk). Tulis "testing environment" bukan "Lab Teknik Industri
    Universitas X" (jika user tidak sebut lokasi).
  ▶ Konsistensi: nama alat/tempat di gambar HARUS sama persis dengan yang
    disebut di teks paper, tabel, dan abstrak.

Isi deskripsi:
  1. Mulai dengan TIPE: "A block diagram...", "A bar chart..."
  2. Jelaskan SETIAP elemen: kotak, label, panah, sumbu, legenda, warna
  3. Tata letak spasial: "on the left", "flowing left to right"
  4. Detail teknis: gunakan info dari user prompt jika ada, generik jika tidak
  5. Akhiri: "White background. Clean, minimal style consistent with
     academic paper figures."
  6. MINIMAL 150 kata — jika kurang, tambahkan detail.

TIPE GAMBAR WAJIB (minimal 6–8 total):
  Fig. 1–2  : Diagram blok arsitektur
  Awal      : Prototipe/rig eksperimen
  Tengah    : Flowchart algoritma
  Akhir     : Grafik kinerja/perbandingan

BAGIAN D  —  PERSYARATAN KONTEN PER SECTION

ABSTRAK (150–250 kata):
  • Buka dengan masalah dunia nyata — bukan "paper ini mengusulkan"
  • Keterbatasan spesifik pendekatan terdahulu
  • Metode + inovasi kunci
  • Minimal 2 hasil/temuan spesifik
  • Dampak atau aplikasi dunia nyata

PENDAHULUAN (450–600 kata):
  ✓ Konteks dunia nyata — industri, negara, institusi, tahun spesifik
  ✓ Tinjauan karya terdahulu + keterbatasan konkret + sitasi
  ✓ Pernyataan masalah spesifik dan terukur
  ✓ 3–5 kontribusi bullet (spesifik, dapat diverifikasi)
  ✓ Paragraf organisasi paper — sebutkan setiap section

TINJAUAN PUSTAKA (300–500 kata per subsection):
  ✓ 5–7 referensi per subsection dengan pola B6
  ✓ 2–3 subsection topik berbeda
  ✓ Perbandingan antar-paper
  ✓ Sintesis: kesenjangan kolektif yang diisi karya ini

METODOLOGI (300–500 kata per subsection):
  ✓ Rasional desain (bukan "kami menggunakan X")
  ✓ Data/sampling/perangkat keras + justifikasi
  ✓ Algoritma/metode + persamaan (jika berlaku)
  ✓ Implementasi + parameter spesifik
  ✓ STEM: minimal 3 persamaan display
  ✓ Kualitatif: abaikan persamaan, gunakan kerangka konseptual

HASIL (250–450 kata per subsection):
  ✓ Hasil utama pada kalimat PERTAMA (pola B7)
  ✓ Analisis-MENGAPA untuk setiap metrik
  ✓ Perbandingan ≥ 3 karya terdahulu
  ✓ Minimal 1 anomali/keterbatasan dibahas jujur
  ✓ Hubungan ke deployment/makna praktis

KESIMPULAN (150–300 kata, 3 paragraf):
  ✓ P1: Ringkasan hasil SPESIFIK (bukan "kinerja baik")
  ✓ P2: Keterbatasan jujur
  ✓ P3: 3+ arah penelitian spesifik dan dapat ditindaklanjuti

VARIASI JUDUL SECTION — pilih sesuai bidang:

BAGIAN F  —  FORMAT TEKS INLINE DI STRING JSON
================================================================================
Renderer DOCX menginterpretasikan escape ini di semua nilai "text" dan sel
tabel "Rows".

── F1. TOGGLE FORMAT ──────────────────────────────────────────────────────────
  \b    toggle TEBAL on/off
  \i    toggle MIRING on/off
  \u    toggle GARIS BAWAH on/off
  $...$  persamaan matematika inline (LaTeX)

ESCAPING JSON: Setiap \ digandakan di string JSON.
  \b → tulis \\b di JSON  |  \i → tulis \\i  |  \u → tulis \\u

SELALU gunakan pasangan toggle:
  ✓ BENAR: "...metode \\byang diusulkan\\b mencapai..."
  ✗ SALAH: "...metode \\byang diusulkan mencapai..."   (tidak ditutup)
  ✗ SALAH: "...metode **yang diusulkan** mencapai..."   (Markdown)
  ✗ SALAH: "...metode <b>bold</b>..."                   (HTML)

── F2. CONTOH ─────────────────────────────────────────────────────────────────
  Tebal metrik:     "akurasi mencapai \\b97.3%\\b pada uji akhir"
  Tebal akronim:    "\\bSTM32F4\\b mikrokontroler (ARM Cortex-M4, 168 MHz)"
  Miring variabel:  "variabel \\ix\\i merepresentasikan perpindahan"
  Garis bawah:      "memenuhi \\ukendala waktu-nyata\\u di Section III"
  Math inline:      "error $e(t) = r(t) - y(t)$ mengendalikan PID"
  Tebal + math:     "mencapai $F_1 = \\b0.947\\b$ pada set uji"

── F3. BOLD BARIS TABEL ───────────────────────────────────────────────────────
  "Rows": [
    ["Metode A [5]",      "89.2%",   "GPU",     "2022"],
    ["Metode B [8]",      "91.7%",   "CPU",     "2023"],
    ["\\bDiusulkan\\b",  "\\bx\\b", "\\bMCU\\b", "\\b2025\\b"]
  ]
  Baris metode yang diusulkan di-bold penuh.

── F4. JANGAN GUNAKAN ─────────────────────────────────────────────────────────
  × **bold**    (Markdown)   × *italic*     (Markdown)
  × <b>bold</b> (HTML)       × \textbf{}    (LaTeX — hanya di $...$)
