TOPIC GUIDE — Game Development
================================================================================
FIELD: Computer Science / Interactive Media
DEFAULT CITATION STYLE: IEEE for technical game-engine papers; APA for game studies, UX, learning, and player-behavior papers
SUBDISCIPLINE: Game Engineering, Game AI, Procedural Content Generation, Serious Games, Player Experience, Game Analytics, Game Production

ABSTRACT CHARACTERISTICS:
  150–250 words. Reports game genre/platform, target player or learning context, technical artifact or design intervention, evaluation method, quantitative player/gameplay metrics, qualitative experience findings, and implications for game design or engine implementation.

INTRODUCTION ELEMENTS:
  - Game context: platform, genre, target audience, interaction mode, production constraints.
  - Technical or design problem: engagement, balance, difficulty adaptation, performance, accessibility, content generation, monetization ethics.
  - Gap in existing games/tools: lack of empirical evaluation, weak AI behavior, limited procedural diversity, poor accessibility, insufficient telemetry.
  - Objective: implement, evaluate, or compare a game mechanic, engine module, AI system, or player-experience intervention.
  - Contributions: playable prototype, algorithm, design framework, user study, benchmark, or analytics pipeline.

LITERATURE REVIEW:
  Common section name: "Related Work" / "Background"
  - Game design theory: mechanics-dynamics-aesthetics, flow, player motivation, immersion, presence.
  - Game engineering: Unity/Unreal workflows, ECS architecture, rendering optimization, physics, networking.
  - Game AI: finite state machines, behavior trees, GOAP, pathfinding, steering, procedural agents.
  - Procedural content generation: search-based PCG, grammar-based levels, wave function collapse, PCGML.
  - Player research: telemetry, game analytics, UX testing, player modeling, churn prediction.
  - Serious games: learning outcomes, health behavior change, training simulation, assessment validity.

METHODOLOGY:
  Common section name: "Methodology" / "Game Design and Evaluation"
  - Design: concept document, mechanic specification, level design, interaction flow, balancing rules.
  - Implementation: Unity/Unreal/Godot prototype, AI controller, physics/collision, shader or networking module.
  - Evaluation: playtesting, A/B test, usability test, telemetry analysis, pre/post learning test, expert review.
  - Metrics: FPS, latency, bug rate, completion time, deaths, retention, engagement, SUS, GEQ, PXI, learning gain.
  - Analysis: descriptive statistics, t-test/ANOVA, regression, survival analysis, thematic coding, mixed-method triangulation.

TYPICAL RESULTS & DISCUSSION:
  - Adaptive difficulty can improve completion and perceived challenge while reducing frustration.
  - PCG quality is discussed through diversity, playability, controllability, and designer effort.
  - Game AI is evaluated using success rate, believability, response time, and computational cost.
  - Serious-game studies report learning gains, transfer, motivation, and usability constraints.
  - Production studies discuss scalability, maintainability, asset pipeline, and team workflow.

TYPICAL FIGURES:
  - Game architecture diagram, state machine or behavior tree, level map, UI flow, gameplay screenshot, telemetry dashboard, FPS timeline.

TYPICAL TABLES:
  - Feature comparison, playtest participant profile, performance benchmark, player metrics, questionnaire results, bug taxonomy, balancing parameter table.

CONCLUSION CHARACTERISTICS:
  - States whether the prototype or intervention improved gameplay, performance, learning, or player experience.
  - Identifies design trade-offs, technical limitations, sample limitations, and production constraints.
  - Suggests future work: larger playtests, multiplayer scaling, accessibility expansion, procedural authoring tools, longitudinal analytics.
