## 3. Arsitektur Baru

### 3.1 Mode-Based Tool Routing

Sebelum: tiap turn kirim full SYSTEM_PROMPT 7.4 KB + 9 tool floor 4.7 KB. "halo" = ~13 KB wire bytes.

Sesudah: 8 mode di `backend/mode_prompts.py`, dipanggil via `get_mode_bundle(mode) -> (prompt, tool_names)`:

| Mode | Prompt | Tools |
|---|---|---|
| `tier0` | 158 B | RouteIntent only |
| `discovery` | 1584 B | RunSLR, GetLiterature, ListAttachedFiles, ReadAttachedFile, GenerateFullPaper, ProposeChips, SetCitationStyle, SetLanguage |
| `slr` | 644 B | 5 tools |
| `edit` | 1121 B | 9 tools |
| `rapikan` | 616 B | 4 tools |
| `revisi` | 1574 B | 10 tools (incl. Paraphrase/FixGrammar/Translate) |
| `memory` | 287 B | ListMemory, DeleteMemory |
| `casual` | 158 B | 0 tools |

Mode disimpan in-memory di `chat.py` (`_CONV_MODE` dict) — restart reset, AI re-classify via RouteIntent.

### 3.2 Auto-Memory (Tidak Pakai Tool Lagi)

`SaveMemory` dan `GetMemory` **dihapus** dari tool list. Backend `auto_memory.py` ekstrak fakta otomatis di hook `chat.py:733` (setelah user msg commit, sebelum generate()):

- Layer 1: Regex untuk `[OPSI]` reply pattern, "1"/"pilih 2"/"yang ketiga", "ingat: X".
- Layer 2: V-DEEPSEEK fallback saat regex miss + expected_key terdeteksi.
- Confidence filter: skip stopword/empty/echo.

Memory di-inject ke system prompt **hanya turn pertama atau saat user explicit ask** (regex `(?i)(ingatan|memori|memory)`).

### 3.4 Generate Paper Pipeline

Sebelum: dua pipeline divergent (chat thread tanpa progress + RQ legacy 90KB call).

Sesudah: **unified chunked dengan checkpoint/cancel/resume.**

`generate_paper_json_chunked()` di `backend/generate_paper_chunked.py`:
- Params baru: `checkpoint_cb`, `cancel_check`, `resume_state`.
- Skip chunks di `resume_state["chunks_done"]`, reuse dari `partial_paper`.
- Class `GenerationCancelled` untuk graceful abort.
- 8 chunks: outline → section_1..5 → references → combine.

Per-chunk prompt sekarang load **full** `prompt.txt` (53KB) + `humanize.txt` (36KB) + chat history + literature catalog + file content (50-130 KB total per call). Trade-off: token cost lebih tinggi tapi quality terjaga sesuai permintaan user di perintah.txt.

`AiJob.paper_id` sekarang **selalu di-set** saat chat-initiated (bug lama: NULL).

`AiJob` row TIDAK di-delete saat GET result (untuk badge inbox).

### 9.4 Bug yang Mungkin Muncul Saat E2E
- **Mode persistence in-memory:** restart backend reset semua mode. AI re-classify via RouteIntent — acceptable cost. Kalau jadi masalah, tambah `Conversation.metadata` JSON column di migration baru.
- **Resume saat literatur baru ditambah:** AI generate section 3-5 dengan literatur baru, section 1-2 dengan literatur lama → potential inconsistency. Ada warning di spec section 6 tapi belum di-implement.
- **Multi-worker gunicorn + SLR_MAX_WORKERS:** efektif `N workers × 10 = 40` total. Set `SLR_MAX_WORKERS=3` kalau gunicorn 4 worker, atau pisahkan SLR jadi proses sendiri.
- **Token cost spike di full prompt mode:** per-chunk 50-130 KB × 8 chunks = bisa 1 MB total per generate. Pastikan rate limit / quota tracking tidak overflow.
- **In-memory `_CONV_MODE` dict bocor:** unbounded growth. Tambah TTL cleanup atau LRU evict kalau jadi memory leak.

### 9.5 Yang Mungkin Ditanyakan User
- "Kenapa SaveMemory hilang?" → backend auto-extract sekarang, tidak perlu AI panggil tool.
- "Gimana tau memory ke-save apa engga?" → log INFO di `auto_memory.py`. Frontend bisa tampilkan via `/api/papers/{id}/memory`.
- "Mode `revisi` belum bisa diakses?" → user harus minta "saya mau revisi" atau AI panggil RouteIntent dengan mode=revisi.
- "Resume kok regenerate dari awal?" → cek `AiJob.result.chunks_done` array; kalau kosong berarti partial save tidak jalan, debug checkpoint_cb.
