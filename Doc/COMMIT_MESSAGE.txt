fix(chat): replace raw PROPOSAL JSON with user-friendly messages

When users requested paper generation or other tool actions via chat,
the system was displaying raw PROPOSAL JSON payloads (e.g.,
<<PROPOSAL>>{"kind":"paper_progress","job_id":"...",...}) instead of
user-friendly confirmation messages.

Root cause: After parsing and handling PROPOSAL payloads in the chat
store, the raw JSON string remained in tc.result and could be displayed
in the chat interface.

Changes:
- Added _getFriendlyProposalMessage() helper function that converts
  PROPOSAL payloads into user-friendly messages based on proposal.kind
- Modified tool result handler to replace tc.result with friendly
  message after successfully parsing and handling the proposal
- Handles 20+ proposal types: paper_progress, slr_job, journal,
  export_docx, title, abstract, keywords, section, reference,
  propose_revisi, chart_proposal, file_review, validation_error,
  multi_question, review_plan, revise_data, chips, setting_saved,
  file_classified, and more

Impact:
- Users now see clean messages like "✓ Paper generation started (job:
  abc123). Editor akan auto-load hasilnya." instead of raw JSON
- Paper data continues to be saved correctly to database
- All existing chat functionality preserved
- No breaking changes

Files modified:
- frontend/src/stores/chat.js (+84 lines)

Testing:
- Frontend builds successfully without errors
- All proposal types handled with appropriate messages
- Both ChatMessage.vue and ToolCallBlock.vue benefit from the fix

Fixes: Paper generation chat UX issue
Related: backend/chat_tools.py, backend/app.py (no changes needed)
