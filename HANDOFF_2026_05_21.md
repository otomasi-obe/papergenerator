Sesi ini fokus ke **editor polish, image-gen queue, file workflow**, dan satu AI tool baru. Semua perubahan sudah build hijau (frontend + Python AST). Belum dijalankan e2e di browser — perlu manual verify di paperfull.app.

## Yang dikerjakan

### Editor — ContentList.vue
- Image content box: thumbnail tetap tampil, tombol Upload/Replace + toggle "Prompt & Generate" dalam satu baris. Prompt **default tertutup**, baru muncul saat user klik toggle.
- Spinner generate gambar **persisten lintas navigasi** — job id disimpan di `item.JobId`, on mount re-attach via `imageGenStore.subscribe()`. Sebelumnya spinner hilang kalau user pindah paper / reload.
- Drag-scroll diperbaiki di semua `<draggable>`: drop `force-fallback`, tambah `bubble-scroll: true`, naikkan `scroll-sensitivity: 200`. Sebelumnya drag mendekati edge tidak bikin panel scroll.
- Dead code `FiguresTab.vue` dihapus (tab Figures sudah hilang dari leftTabs sejak lama).

### Editor — PaperEditorPage.vue
- Drag-scroll fix dipropagasi ke draggable sections, subsections, authors, references.

### FilesTab.vue
- Full dark mode — semua `bg-white/border` ditukar token `bg-cream-50/dark:bg-ash-800` + `border-cream-300/dark:border-ash-700`. Box putih di dark mode hilang.
- Upload progress indikator (`Uploading… (50%)`).

### ChatTab.vue
- Tombol `+` jadi **2-opsi menu**:
  - **Upload baru** → file picker (PDF/DOCX/DOC, multi)
  - **Pilih file paper ini** → dialog list file yang sudah di-upload (centang multi)
- File yang dipilih dari paper-file picker **tidak di-upload ulang** — diambil text-nya via `/api/papers/{id}/files/{fid}/preview`, di-flag `__preExtracted: true`, lalu `handleSend()` bypass round-trip extraction.
- Cap attach naik dari 5 → 10 file.

### Backend
- `files_bp.py`: shared `ThreadPoolExecutor(max_workers=20, thread_name_prefix="pdf-extract")` di module-level. Endpoint `POST /api/papers/{id}/files` sekarang phase-1 read+save sync, phase-2 ekstrak paralel via pool, phase-3 commit batch. Sebelumnya sequential — upload 10 PDF ~30s+, sekarang ~5-8s.
- `app.py /api/upload-pdfs` (legacy chat path): import `_EXTRACT_POOL` dari files_bp, cap naik 5 → 10.
- `chat_tools.py`: tool baru **`GetPaperNumbering`** — return ordered list figures/tables/equations dengan label asli (`Fig. 1`, `Table II`, `Eq. (3)`) + parent section. AI pakai ini untuk rapikan referensi prose setelah user reorder content boxes.
- `chat.py`:
  - Keyword router: tambah pemicu untuk `GetPaperNumbering` (rapikan, renumber, urutkan, dst.) + tambah `rapikan` ke ProposeSection triggers.
  - System prompt: section "EDITING EXISTING PAPER" tambah instruksi explicit — pas user bilang "rapikan", AI **harus** call `GetPaperNumbering` → `GetPaperContent` → `ProposeSection` per section yang sebut Fig./Table/Eq.

### Image queue — verifikasi (sudah ada sebelumnya)
- 4 worker thread, 1 per akun Gemini (`account1..4`), strict sequential per worker — confirmed di `backend/image_worker.py`.
- `ImageGenJob` di-persist di DB → recovery setelah restart proses (running di-demote ke queued; browser session hilang).
- Frontend `imageGen.js` punya shared poller 3s, plus `resume()` dipanggil `onMounted` PaperEditorPage → re-hydrate dari `/api/image-jobs` user.

## Konteks teknis penting

- **`item.JobId`** baru — field baru di item gambar. Akan di-persist ke DB lewat existing `paper.data` JSON column otomatis. Tidak perlu migrasi.
- **Cap PDF jadi 10** — frontend (`addAttachedFiles` slice 10) + backend (`MAX_PDF_FILES = 10`) sinkron. Kalau ubah salah satu, ubah dua-duanya.
- **Pool size 20** — module-level singleton di `files_bp.py`. Kalau backend run dengan multiple workers (gunicorn `-w 4`), total threads = 4 × 20 = 80. Sesuaikan kalau prod pakai banyak gunicorn worker.
- **Image queue UI dependency**: `ContentList.vue` sekarang pakai `imageGenStore.getJob()` + `subscribe()`. Pastikan `useImageGenStore().resume()` dipanggil di mount (sudah di `PaperEditorPage.vue:387`).
